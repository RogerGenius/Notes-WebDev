# 依赖引入

**概述：** Gateway 基于 Spring WebFlux 构建，==与 spring-boot-starter-web（Servlet 阻塞模型）互斥==，必须排除 `spring-boot-starter-web` 依赖。

```xml
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-gateway</artifactId>
    <exclusions>
        <exclusion>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-web</artifactId>
        </exclusion>
    </exclusions>
</dependency>
```

**概述：** 如果父 POM 中已引入 `spring-boot-starter-web`，子模块必须显式排除，否则启动时会抛出 `Spring MVC found on classpath` 异常。

# 注册中心依赖

**概述：** Gateway 需要配合服务注册中心使用 `lb://` 协议实现负载均衡路由。以 Consul 为例：

```xml
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-consul-discovery</artifactId>
</dependency>
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-loadbalancer</artifactId>
</dependency>
```

# application.yml 路由配置

**概述：** Gateway 的核心配置在 `spring.cloud.gateway.routes` 下，每条路由包含 ID、目标 URI、断言和过滤器。

```yaml
server:
  port: 8088

spring:
  application:
    name: gateway
  cloud:
    consul:
      host: localhost
      port: 8500
      discovery:
        heartbeat:
          enabled: true
    gateway:
      routes:
        - id: mall-product
          uri: lb://mall-product
          predicates:
            - Path=/mall-product/**
          filters:
            - StripPrefix=1

        - id: mall-order
          uri: lb://mall-order
          predicates:
            - Path=/mall-order/**
            - Query=name
            - Query=age
          filters:
            - StripPrefix=1
```

| 配置项 | 说明 |
|-------|------|
| `id` | 路由唯一标识，自定义命名 |
| `uri` | 目标服务地址。`lb://服务名` 表示使用负载均衡，服务名对应 `spring.application.name` |
| `predicates` | 断言列表，所有条件满足时才匹配 |
| `filters` | 过滤器列表，按顺序执行 |
| `StripPrefix=1` | 去除请求路径的第 1 段前缀。`/mall-product/api/list` → `/api/list` |

**概述：** 路由转发示例：浏览器访问 `http://localhost:8088/mall-product/pms-product/play`，Gateway 匹配 `mall-product` 路由，去除第 1 段前缀后转发到 `http://mall-product实例/pms-product/play`。

# 路由断言配置

## Path 断言

```yaml
predicates:
  - Path=/api/**
```

## Method 断言

```yaml
predicates:
  - Path=/web/**
  - Method=GET
```

**概述：** 仅允许 GET 请求通过，其他方法返回 404。

## Query 参数断言

```yaml
predicates:
  - Path=/web/**
  - Query=name
  - Query=age
```

**概述：** 请求必须同时包含 `name` 和 `age` 参数才会被路由。示例：`http://localhost:8088/web/student/my?name=tom&age=20`。

## Header 断言

```yaml
predicates:
  - Header=X-Token, \d+
```

**概述：** 请求头中必须包含 `X-Token` 且值匹配正则 `\d+`。

# 负载均衡配置

**概述：** Gateway 的负载均衡通过 `lb://` URI 协议自动实现。==多个服务实例只需将 `spring.application.name` 设为同一值==，Gateway 默认使用轮询策略分发。

```yaml
# 服务实例 A —— mall-order（端口 8081）
spring:
  application:
    name: mall-order
server:
  port: 8081

# 服务实例 B —— mall-order（端口 8082）
spring:
  application:
    name: mall-order
server:
  port: 8082
```

**概述：** 无需修改 Gateway 路由配置，两个实例注册到 Consul 后自动被发现并参与负载均衡。

# 全局过滤器配置

**概述：** 自定义全局过滤器实现 `GlobalFilter` 接口，可用于鉴权、日志等全局处理。

```java
@Component
public class AuthGlobalFilter implements GlobalFilter, Ordered {
    @Override
    public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
        String token = exchange.getRequest().getHeaders().getFirst("Authorization");
        if (token == null || token.isEmpty()) {
            exchange.getResponse().setStatusCode(HttpStatus.UNAUTHORIZED);
            return exchange.getResponse().setComplete();
        }
        return chain.filter(exchange);
    }

    @Override
    public int getOrder() {
        return 0;
    }
}
```

# 跨域配置

**概述：** Gateway 的全局跨域配置通过 YAML 完成，无需编写代码。

```yaml
spring:
  cloud:
    gateway:
      globalcors:
        cors-configurations:
          '[/**]':
            allowedOrigins: "*"
            allowedMethods:
              - GET
              - POST
              - PUT
              - DELETE
            allowedHeaders: "*"
            allowCredentials: false
```

# 常见问题

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 启动报 `Spring MVC found on classpath` | 同时引入了 `spring-boot-starter-web` | 排除 `spring-boot-starter-web` 依赖 |
| `lb://` 路由报 503 | 注册中心中无该服务或未引入 `loadbalancer` 依赖 | 检查服务注册状态和依赖 |
| 断言不匹配返回 404 | Path / Query / Method 等条件不满足 | 检查请求路径和参数是否匹配配置 |
| 过滤器执行顺序异常 | 未正确实现 `Ordered` 接口 | 通过 `getOrder()` 设置执行优先级 |
| 跨域配置不生效 | 后端服务也设置了 CORS，导致双重响应头 | 仅在 Gateway 层配置跨域，移除后端 CORS 配置 |
